## 关键观察

1. **errors** 是叶子，**所有** crate 依赖它（强约束：统一错误类型）
2. **observability** 不依赖任何业务 crate，但**所有**业务 crate 依赖它
3. **server** 是胖 binary（依赖 9 个 crate），是部署单位
4. **admin** 不依赖 ai/agent/git（独立鉴权域的设计强约束）
5. **cli** 极简（仅 errors/config/core），可独立发布

## 依赖反转（重要）

- proto 自动生成的代码不应被 **core** / **graph** 等基础 crate 依赖（避免循环）
- proto 应在 Layer 1，由 server / admin 在 binary 层使用
